# API Contract

Base: FastAPI, JSON in/out. Backing types are defined in `data-model.md`. Frontend should mock these responses before backend is live.

## GET /api/health
Response: `{"status":"ok"}`

## POST /api/scenario/generate
Request: `{"scenario_name":"peak","seed":42}`
Response: `{"scenario": ScenarioConfig, "arrivals": SyntheticArrivalData, "baseline": AllocationPlan}`.

## POST /api/scenario/baseline
Request: `ScenarioConfig`
Response: Authoritative deterministic `AllocationPlan` (label="baseline").

## POST /api/forecast
Request: `{"scenario": ScenarioConfig}`
Response: `ForecastResult`.

## POST /api/simulate
Request: `{"scenario": ScenarioConfig, "forecast": ForecastResult, "allocation": AllocationPlan}`.
`forecast` and `allocation` queue IDs must exactly match the scenario queues;
allocation staff must respect each queue's min/max and the total staff budget.
Response: `SimulationResult`.

## POST /api/optimize
Request: `{"scenario": ScenarioConfig, "forecast": ForecastResult}`
Response: `OptimizationResult` including baseline, optimized allocation, score breakdown, improvement, explanation, and feasibility.

## POST /api/whatif
Request: `{"scenario": ScenarioConfig, "forecast": ForecastResult, "allocation": AllocationPlan}`.
Response: `SimulationResult`, identical in shape to `/api/simulate`.

## POST /api/explain
Request: `{"scenario": ScenarioConfig, "optimization": OptimizationResult}`.
Response: `{"explanation": string}` generated by the deterministic explanation engine.

## Error format
```json
{"detail":{"error":"short machine-readable code","message":"human-readable explanation","field":"optional offending field"}}
```
Business-rule validation uses this shape. Malformed JSON and schema errors use FastAPI's standard 422 `detail` list. Use 4xx for client/input errors and 5xx only for genuine server faults.

## Versioning
No API versioning is required for the hackathon scope. Contract changes after dependents exist must be announced and documented in the same PR.
