# UX Principles

## Audience
Branch operations manager and hackathon judges seeing the dashboard for the first time. The story should be obvious without narration.

## Principles
1. Show the problem before the solution: overload must be visually obvious before optimization.
2. Numbers over adjectives: claims on screen must be real computed numbers.
3. One primary action at a time: view state → alert → optimize → recommendation → comparison → what-if.
4. Explainability is a first-class panel, not a tooltip.
5. What-if should feel instant, targeting sub-2-second feedback.
6. Loading, empty, and error states are explicit requirements.

## Visual language
Use consistent visual treatment for problem/overload and resolved/optimized states. Keep charts simple, labeled, and free of unnecessary 3D. Use one scrollable page for the demo.
